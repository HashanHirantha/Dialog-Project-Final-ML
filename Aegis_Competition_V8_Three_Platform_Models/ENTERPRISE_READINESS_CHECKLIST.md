# Enterprise Readiness Checklist — ML Scope vs Whole Platform

**Working in V6:** 90-day account features, DB-backed source data, approved scoped AD catalog, historical AD observations, unreviewed transfer mandatory queue, status/evidence separation, isolation-forest training/scoring, per-cycle parameters, independent full-manual pilot tools, calibration with explicit missed-case tolerance, source-drift reports, model artifact digest/optional HMAC, migration revision, per-account human-review evidence and automated backend tests.

**Log Collection Team:** Build/test live Windows Event Forwarding or event agent, Linux journald/auditd normalization, GitHub/GitLab and application entitlement inventories; real HR/directory exports; ingestion completeness and idempotency/permissions. Confirm log events genuinely correspond to exercised grants. Handle time zones and cross-platform identity collisions.

**API/Platform Team:** Secure tenant boundaries/organization DB isolation, authorization and ownership of group catalog changes, service-to-service authentication, migration deployment sequence, background 90-day jobs, bounded pagination and worker retries, pilot file isolation and blind-review UI, audit retention and signed export, escalation of mandatory/deferred/evidence-gap work, confidential data protection, secrets rotation, approval of configuration changes, controlled remediation/verification only after authorization.

**ML Team Next:** (a) source-based coverage quality at application/grant level; (b) hierarchical/nested group resolution when accurate enterprise exports permit it; (c) label adjudication and class-imbalance analysis; (d) time-aware per-company validation, not cross-company leakage; (e) platform/cohort fairness and drift; (f) multiple-cycle parallel manual pilot; (g) evaluate rules-only vs hybrid and alternatives only if warranted; (h) performance benchmark with real 80k-accounts DB load; (i) model registry and rollout/rollback, access-controlled signed artifacts.

**Release blockers:** No independently reviewed enterprise dataset; no company-signed group catalog; no agreed acceptable missed-case tolerance; no pilot B; no formal policy approval for deprioritizing mandated reviews; no measured sustained DB/API throughput; no verified end-to-end identity/authorization in a real tenant. V6 must be described as **enterprise-oriented ML engineering prototype**, NOT an enterprise production-ready access-governance service.
